# 设计哲学

## 一、问题

现在的 AI 会这样生成界面：

> 「这是电话簿」→ 搜索框 + 列表 + 按钮。

每个元素单独看都合理，但没人想过它们为什么在这里。结果就是**有控件，没引导**——用户拿到界面，不知道该点哪里。

## 二、主张

**美是功能的副产品。**

界面的首要使命不是好看，是让用户在拿到它的第一秒就知道该做什么。

## 三、三问

用户面对任何一个界面，心里只有三个问题：

| 问 | 真正的意思 |
|---|---|
| **我从哪来** | 我为什么会在这一屏？是搜出来的，还是被推过来的？ |
| **我到哪去** | 我现在该点哪里？ |
| **我回哪去** | 我做完之后，怎么落地？会不会卡在这里？ |

三个里最重要的是**「我到哪去」**。来路忘了、退路模糊，只要用户知道当下该点哪里，界面就还能用。反过来，不知道下一步该干什么，界面就是一堆死信息。

## 四、方法

**从意图反推设计，而不是从组件正推。**

现在的 AI 是正推：看到「电话簿」就调出「搜索框 + 列表 + 按钮」的模板。
苏格拉底美学是反推：先问用户此刻的第一意图是什么，再推这个意图需要什么形态。

推导只有四步：

```
1. 用户此刻最想干的那一件事是什么？      → 只有一个
2. 这个元素服务那件事吗？                  → 答不上来就删
3. 要服务它，形态必然是什么样？            → 形状/大小/位置由此推出
4. 把它拿掉或换掉，会在哪一步断掉？        → 断得越狠，越不可替代
```

## 五、举例：电话簿

用户的意图是**找到某个人，打给他**。于是：

- **主按钮是圆的大触点，不是方形。** 圆形代表「碰一下就发生」，电话簿的终点动词是呼叫，不是查看。
- **搜索框是长条，不是圆形。** 圆是「按」的语义，长条是「填」的语义。形状跟着意图走。
- **搜索框吸顶。** 用户往下翻着找人，翻了很久没找到，心理会从「悠闲浏览」变成「赶紧搜」。吸顶保证他从浏览切到搜索的距离是 0。
- **列表按最近/高频排，不是 A–Z。** A–Z 是数据库的排序方式，把找人的成本转嫁给了用户。

## 六、同一个功能，意图变了，形态就变

如果这个通讯录不是私人电话簿，而是**客服工单通讯录**——用户的意图变成「确认这人对不对、是不是负责我这单的」：

- 最高权重的**不再是圆形呼叫按钮**，而是一块说清身份和工单的**信息条**
- 主按钮变成**「查看工单」**
- **电话图标降级**，甚至藏进详情页

在这个时候放大圆呼叫按钮，用户还没确认身份就拨通了，会社交尴尬，也会走错流程。

**所以形状不是风格选择，是意图推导的结果。**

## 七、这套东西是什么

**它是一套推导方法，不是一套设计规范。**

- 规范说：「电话簿主按钮用 56px 圆形悬浮按钮。」——这是死教条。
- 推导说：「当核心意图是即时呼叫时，形态收敛为圆形；当核心意图是核验身份时，形态收敛为信息条。」——这是活的因果。

规范只是推导结果在某个条件下的存档。条件变了，规范失效，推导依然成立。

## 八、不适用

- 游戏、互动叙事——要的就是迷雾和不确定
- 骗点击的营销落地页——目的就是剥夺用户的理智
- 纯艺术装置——要的是情绪，不是效率

除此之外，生产力工具、业务系统、公共服务、交易、数据界面，都适用。
