# Apologia-ui｜苏格拉底美学

## 这是什么

**一套认知推导方法，不是一组组件设计规范。**

静态规范说：「电话簿主按钮用 56px 圆形悬浮按钮。」——这是教条，是死物。
苏格拉底推导说：「当核心意图是即时无阻呼叫时，形态必然收敛为圆形；当核心意图是工单核验时，形态必然收敛为信息长条。」——这是因果，是活的。

规范只是推导结果在特定条件下的**切片存档**。当条件变了，规范失效，推导依然成立。

## 病根

当前 AI 生成界面的失败方式是**正推**：识别到「这是电话簿」→ 输出「搜索框 + 列表 + 按钮」→ 每个元素单独看都合理，但没有任何一个是从用户意图推出来的。结果是**有控件，没引导**。

用户拿到界面后，无法在瞬间判断「我现在该点哪里」。

## 推导函数

```
输入：场景 + 用户进入时的认知状态
 ↓
① 判读意图类别      → 查 core.md 常数一（五类意图罗盘）
② 判读失败代价      → 查 core.md 常数二（频率 × 失败代价）
③ 确立主意图唯一性  → 一个视图一个主语
④ 剔除              → 无法自证因果的元素，无权存在
⑤ 推导形态必然性    → 形状/尺寸/位置由意图推出，不由组件库决定
⑥ 排布视觉权重      → 主意图最高，其余依次降级
⑦ 铺退路            → 意图突变时的兜底安全阀
⑧ 反证自检          → 拿掉它 / 换掉它，因果在哪一环断裂
 ↓
输出：意图推导 → 结构化组件树 + 间距层级 + 交互状态机 + 可执行代码
```

**第 ⑧ 步是本体系的判决方式。** 判定一个设计对不对，不靠「哪种更好看」，靠反证：把这个元素拿掉、或换成另一个形态，因果链会在哪一环断裂。断得越狠，这个元素越不可替代。

## 三问

推导全程围绕三问，它们是检查表，不是口号：

| 问 | 本质 | 真正的判定对象 |
|---|---|---|
| 我从哪来 | 心智因果为主，空间层级为辅 | 用户带着什么认知状态、在什么断点下触发当前场景 |
| 我到哪去 | 微观动作必须单向收敛于宏观意图 | 这个界面为主意图铺的滑轨，阻力是否最小 |
| 我回哪去 | 心智释放与确定性锚点，不是历史回退 | 行为结束后，用户能否确认「我安全着陆了」 |

**优先级：唯一保底项是「到哪去」。** 用户暂时忘了来路、退路暂时模糊，只要界面能瞬间告知「当下该做什么、点这里能推进什么」，可用性就不会归零。没有「到哪去」，界面立刻退化为无意义的信息死水。

## 对内诘问律

每一个像素、尺寸、颜色、几何形都必须经受冷酷推敲：

> 「为什么是圆的？」「为什么放右边？」「删掉它系统会瘫痪吗？」

答不上来的元素，无权存在。

对外是助产术——用最明确的视觉线索，把用户脑中模糊的意图顺畅催生出来。对内是诘问——用最冷酷的因果，把所有无法自证的表达剔除干净。

## 适用的边界

**适用**：一切生产力工具、业务系统、公共服务、移动工具、交易链路、数据决策界面。

**不适用**（不要在此套用本引擎）：
- 游戏与互动叙事——需要故意的迷雾、不确定性与探索感
- 投机型落地页——其商业目的即为利用认知偏差剥夺理智
- 纯概念艺术装置——追求情绪震荡而非决策效率

## 与现有规范体系的关系

**上位哲学准则与正当性裁判**，不是平级替代。

| 体系 | 定位 |
|---|---|
| Nielsen 启发式 | 事后的体检与纠错表 |
| HIG / Material Design | 施工现场的标准预制构件库 |
| **苏格拉底美学** | 赋予规范正当性的**立法者** |

它盘问 Material 的 FAB 为什么出现在这里，盘问 iOS 的分段控件凭什么承载这类切换，终结「因为组件库有，所以我顺手放一个」的无脑套用。

HIG 与 Material 仍然是用材库——本引擎负责决定**用什么、为什么用**，它们负责**怎么造得规范**。

## 分册的统一结构

每份分册固定四段。**顺序不可颠倒，尤其不可跳过第 1 段直接看第 4 段。**

| 段 | 作用 |
|---|---|
| **1. 意图归属** | 这个元素在五类意图中各服务于哪一类。不判定意图就使用本分册，等于套用静态规范 |
| **2. 形态必然性** | 从意图推导形状/尺寸/位置的过程。这是发动机本体 |
| **3. 反证** | 拿掉它、或换成别的形态，因果链在哪一环断裂 |
| **4. 切片存档** | 推导结果的固定值。**这些是结论，不是法律**——仅当第 1 段的意图成立时有效 |

## 输出纪律

**禁止在未完成意图判读的情况下直接输出界面代码。**

必须先交付意图推导，再交付实现。第一阶段说明「第一性意图是什么」以及「形态为何必然如此」；第二阶段基于推导结论输出组件树、间距层级、交互状态机与可执行代码。

跳过第一阶段直接给代码，即为违规。

## 交付前的自检

输出前逐条确认：

1. 主意图是否唯一？一个视图是否只有一个主语？
2. 每一个存在的元素，能否用「因为……所以必须……」说清因果？
3. 主意图元素的视觉权重，是否明确高于其余所有元素？
4. 用户行为结束后，「我安全着陆了」这个确认是否成立？
5. 意图突变时（扫视受挫、临时改变主意），是否有 0 距离的兜底路径？
6. 是否混入了无法被因果律证伪的纯装饰？
