# 引擎常量

推导函数只有两个输入。**不判读这两个常数，就无法启动推导**——直接进分册看固定值，等于套用静态规范，违规。

---

## 常数一：五类意图罗盘

用户进入任何一个界面时，认知状态只有五种。**这与用户是谁无关**——医生、程序员、小说家的通讯录里装的人不同，但打开电话簿时的意图类别完全相同。

角色是内容变量，不是形态变量。

### 寻的（Hunt）

- **用户状态**：知道要什么，正在找它。
- **判读特征**：目标可命名、可输入；用户第一动作是打字或扫读。
- **形态必然收敛为**：搜索/直达入口权重最高。
- **成败判据**：第一结果的命中率。命中率低，则意图类别判错，或数据排序逻辑背叛了意图。
- **典型误判**：把「寻的」做成 A–Z 归档列表。A–Z 是系统的索引思维，把检索成本转嫁给了用户的心智算力。

### 续接（Resume）

- **用户状态**：接着上次干，或延续重复行为。
- **判读特征**：存在历史状态、进行中的对象、高频重复动作。
- **形态必然收敛为**：最近 / 进行中置顶，恢复上次位置，操作可断点继续。
- **成败判据**：用户从打开到继续动作的距离。这个距离超过一次点击，意图就被背叛了。
- **典型误判**：每次都让用户从空白的入口重新开始。

### 核验（Inspect）

- **用户状态**：要确认事实，还没决定行动。
- **判读特征**：用户在问「这人对不对」「这单是不是我的」「这数字可信吗」。
- **形态必然收敛为**：结构化信息权重最高，**主动作降级**。
- **成败判据**：用户能否在不产生副作用的前提下完成确认。
- **典型误判**：在核验场景放一个高权重的立即执行按钮。此时贸然执行是高风险误操作——用户还没确认身份就拨通，会产生社交尴尬与流程错误。高权重必须给信息，不给动作。

### 执行（Execute）

- **用户状态**：走完流程，完成一件多步骤的事。
- **判读特征**：有明确终点，需连续输入或多次确认。
- **形态必然收敛为**：每屏只问一个决定，步数可见，进度可回退。
- **成败判据**：完成率与中途放弃率。
- **典型误判**：一屏塞满所有字段，把决策成本一次性压给用户。

### 探索（Explore）

- **用户状态**：没有明确目标，在浏览。
- **判读特征**：用户答不出自己要找什么；动作以滑动、翻看为主。
- **形态必然收敛为**：浏览流与信息密度优先，出口多。
- **成败判据**：用户能否在浏览中找到下一个兴趣点，并随时脱身。
- **典型误判**：对探索意图强加唯一主按钮，把用户的随意浏览变成被迫承诺。

### 判定纪律

1. **主意图的归属单位是「当前视图」，不是「整个 App」。** 同一 App 里列表页是「寻的」、详情页是「核验」，这是正常的。
2. **意图类别可以跨视图切换，形态语言不可互相矛盾。** 同为「核验」的两个页面，信息层级必须同构。
3. **一个视图只允许一个主意图。** 存在多个时，按用户进入该视图时的第一动作裁决。

### 边界情形归属

| 情形 | 归属 | 附加约束 |
|---|---|---|
| **切换**（在多个并行对象间来回跳） | 不单列。视触发状态归入「寻的」或「续接」 | 必须提供对象间直接跳转，且切走后能回到原处，不允许丢掉并行关系 |
| **设置** | 归入「探索」 | 设置页不得成为任何高频意图的入口。高频功能埋进设置＝意图链被切断 |

## 常数二：频率 × 失败代价裁决表

意图类别决定**形态**，代价决定**权重与确认强度**。两者相乘才是完整输入。

|  | 失败代价低 | 失败代价高 |
|---|---|---|
| **高频** | 一步直达，可撤销 | 显眼 + 二次确认 + 明确后果 |
| **低频** | 收进次级入口 | 深藏 + 复述对象 + 强确认 |

### 判读失败代价的三问

1. 做错了，能不能一键撤销？
2. 做错了，损失的是时间、数据，还是关系？
3. 做错了，用户当场能发现，还是几天后才发现？

**三个都偏向坏的一侧 → 高代价，必须二次确认并复述对象。**

### 判读频率的依据

依据是**动作在用户既有习惯中的重复度**，不是产品经理期望的点击量。

人类打开通讯录，80% 的场景是在延续既有的社交与工作因果。这个 80% 就是频率判读的唯一来源。

### 强制规则

- 高代价动作**必须复述对象**。「删除项目 A」合法，「确定要执行此操作吗」违规。
- 高代价动作**不得与主按钮相邻**，防止误触。
- 禁用态**必须说明原因**，不允许静默灰掉。
- 危险操作**不得提供默认值**。

## 两个常数的合成

```
形态 = f(意图类别)
权重与确认强度 = g(频率, 失败代价)
最终设计 = 形态 × 权重
```

**只算形态不算权重，等于知道该用什么控件、不知道该把它放多大；只算权重不算形态，等于知道该强调什么、不知道该强调成什么样子。**

两者都算完，才能进分册查切片存档。

## 装饰的合法性判据

纯装饰原则上非法。唯一豁免条件是它能被**因果律证伪**：

| 判为噪音（非法） | 判为认知降噪功能（合法） |
|---|---|
| 无意义的漂浮背景光 | 微渐变消解了信息分界的生硬感 |
| 为了打破留白而强加的装饰线 | 微动效清晰演示了元素位移的因果关系 |

**判据只有一条：删掉它，用户的认知负担是变重了，还是没变？** 没变 → 删。变重了 → 它是功能，不是装饰。
