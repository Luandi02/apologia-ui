# 表格 Table

表格、数据展示、大列表。

## 1. 意图归属

表格主要服务两类意图：

| 意图 | 表格承担的职责 |
|---|---|
| 寻的 | 从大量数据中定位到某一个 |
| 核验 | 横向比较多个对象，判断事实 |

**判据：表格不是数据库导出视图。字段按数据库顺序排列、按创建时间排序，是系统索引思维，不是用户意图。**

## 2. 形态必然性

### 推导一：表头必须吸顶

- **意图**（核验）：用户滚动查看数据时，必须始终知道每一列是什么。
- **推导**：表头随滚动消失时，用户在第三屏看到数字却忘了它属于哪一列，必须来回滚动比对。
- **结论**：表头固定，不随内容滚动消失。

### 推导二：第一列是可识别标识

- **意图**（寻的）：用户是靠「人 / 对象」来定位的，不是靠序号。
- **推导**：第一列是序号时，用户无法从数据本身识别目标，必须去读第二列。
- **结论**：第一列为名称或编号等可识别标识。

### 推导三：对齐规则全局统一

- **意图**（核验）：比较依赖同位数对齐。
- **推导**：数字左对齐时，位数不同的数字无法快速比较大小。
- **结论**：数字右对齐，文本左对齐，状态居中。

### 推导四：来源与范围必须可见

- **意图**（从哪来）：用户需要确认自己正在看的是哪一批数据。
- **推导**：显示「共 348 条 · 筛选：进行中」时用户才有可信的边界感；否则他看到的是一个不知范围的切片。
- **结论**：显示总数、当前筛选条件、当前条数范围。

### 推导五：超 6 列必须收敛

- **意图**：主意图列不能被横向滚动推到屏幕外。
- **推导**：列数过多 → 横向溢出 → 关键列与操作列都需滚动才能看到。
- **结论**：超过 6 列时，低频列默认隐藏或收进「列设置」。

### 推导六：空结果必须给出路

- **意图**（回哪去）：删除最后一条后，用户不能掉进白屏。
- **推导**：纯白屏时用户无法判断「是没有数据」还是「加载失败」，也没有回到有数据状态的路径。
- **结论**：空状态说明原因 + 提供清除筛选或新建入口。

## 3. 反证

| 拿掉 / 换掉什么 | 因果在哪一环断裂 |
|---|---|
| 表头不吸顶 | 第三屏的数字失去列名，用户必须来回滚动比对 |
| 第一列放序号 | 用户无法从数据本身识别对象，必须再读一列 |
| 数字左对齐 | 位数不同的数字无法快速比较大小，比较意图落空 |
| 不显示总数与筛选条件 | 用户不知道自己在看哪一批数据的切片，无法信任结论 |
| 12 列全部平铺 | 横向溢出，操作列被挤出屏幕 |
| 空结果只给白屏 | 用户无法区分「无数据」与「加载失败」，且无路可回 |
| 行内放 5 个操作按钮 | 行高失控，扫读节律断裂，决策成本前置 |

## 4. 切片存档

| 项 | 值 | 生效条件 |
|---|---|---|
| 行高 | 紧凑 40px ／ 常规 48–56px | 按信息密度判定 |
| 单元格左右内边距 | ≥ 12px | 恒定 |
| 表头字重 | 高于正文 | 恒定 |
| 斑马纹 / 分隔线 | 二选一，不叠加 | 恒定 |
| 主操作位置 | 表格右上方 | 恒定 |
| 列数上限（不折叠） | 6 | 超出则启用列设置 |
| 行内操作数 | ≤ 2 | 恒定 |
| 分页显示 | 第 X–Y 条，共 N 条 | 存在分页时 |
| 排序指示 | 显式当前字段与方向，可取消 | 存在排序时 |

> 以上是推导结论，不是法律。当意图判读改变时，需重新走第 2 段。
