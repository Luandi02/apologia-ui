# 表单 Form

输入、校验、多步流程。

## 1. 意图归属

表单主要服务「执行」意图——用户正在走完一件多步骤的事。

| 意图 | 表单承担的职责 |
|---|---|
| 执行 | 每屏只问一个决定，步数可见，进度可回退 |
| 寻的 | 输入即检索时，输入过程本身就是意图表达，结果须实时反馈 |

**判据：一屏塞满所有字段，是把全部决策成本一次性压给用户，属于对「执行」意图的背叛。**

## 2. 形态必然性

### 推导一：标签常驻

- **意图**（回哪去 / 从哪来）：用户填到一半被打断后，必须能重新认出每一栏是什么。
- **推导**：placeholder 当标签时，用户一开始输入，栏位含义就消失，中断即失忆。
- **结论**：标签独立于输入内容，常驻可见。

### 推导二：失焦校验格式，提交校验完整性

- **意图**：不制造额外阻力。
- **推导**：输入第一个字符就报错，是在用户还没表达完意图时打断他，错误率与放弃率同时上升。
- **结论**：格式错误在失焦时报，遗漏在提交时报。

### 推导三：错误信息说明怎么改

- **意图**（到哪去）：错误提示本身必须是一条滑轨，把用户推回正确路径。
- **推导**：「格式错误」只告知失败，不给出路，用户需要自己猜规则。
- **结论**：错误文案包含正确做法或示例。

### 推导四：焦点自动跳到第一个错误字段

- **意图**（到哪去）：消除用户寻找错误的成本。
- **推导**：长表单提交失败后，错误可能在任何位置，用户必须通篇扫读。
- **结论**：提交失败后焦点落在第一个错误字段，并滚动到可见区。

### 推导五：多步流程必须可见、可回

- **意图**（回哪去）：用户在任何一步都需要知道还剩多少、能否退。
- **推导**：不显示步数 → 用户无法预估投入；不可回退 → 已填内容成为沉没成本，用户被迫走完。
- **结论**：显示「第 X / 共 Y 步」，回退不丢已填值。

## 3. 反证

| 拿掉 / 换掉什么 | 因果在哪一环断裂 |
|---|---|
| 用 placeholder 当标签 | 用户输入后栏位含义消失，中断即失忆，填错率上升 |
| 输入第一个字符就报错 | 在意图尚未表达完时打断，用户被迫与校验器对抗 |
| 错误只写「格式错误」 | 不给出路，用户需要自己猜规则，反复试错 |
| 提交失败不跳焦点 | 长表单需通篇扫读才能找到错误位置 |
| 去掉步数显示 | 用户无法预估投入，中途放弃率上升 |
| 回退丢已填值 | 已填内容变成沉没成本，用户被强制走完流程 |
| 危险字段给默认值 | 用户直接提交默认值，造成不可逆后果 |

## 4. 切片存档

| 项 | 值 | 生效条件 |
|---|---|---|
| 输入框高度 | ≥ 40px | 恒定 |
| 标签与输入框间距 | ≥ 4px | 恒定 |
| 字段间垂直间距 | ≥ 16px | 恒定 |
| 错误文案位置 | 字段正下方 | 恒定 |
| 错误 / 成功色 | 全局各一套，不互相复用 | 恒定 |
| 必填标记 | 统一方式 + 提供总数总览 | 存在必填项时 |
| 校验时机 | 失焦报格式 / 提交报完整性 | 恒定 |
| 步数显示 | 第 X / 共 Y 步 | 多步流程 |

> 以上是推导结论，不是法律。当意图判读改变时，需重新走第 2 段。
