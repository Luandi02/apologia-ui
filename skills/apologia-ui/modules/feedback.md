# 反馈 Feedback

空状态、加载、报错、成功。

## 1. 意图归属

反馈**横跨全部五类意图**——它是所有意图的共同地基。

| 意图 | 反馈承担的职责 |
|---|---|
| 全部 | 确认系统已接收用户的动作，并告知下一步 |

**判据：反馈不是客服式的道歉，而是「保持现场 + 给出出路」。** 用户在任何异常状态下，都必须能回答两个问题：现在发生了什么？我接下来能做什么？

## 2. 形态必然性

### 推导一：空状态必须说明「为什么是空的」

- **意图**（从哪来）：用户必须知道这片空白是他的处境造成的，还是系统的状态。
- **推导**：只显示「暂无数据」时，用户无法区分「从未有过」「被筛选掉」「没有权限」，只能猜测。
- **结论**：三类空状态必须区分，文案各不相同。

### 推导二：每种空状态必须给出路

- **意图**（到哪去）：空白页本身必须是一条滑轨。
- **推导**：无出口的空状态是一口死井——用户看到它，但什么也做不了。
- **结论**：空状态必须携带一个动作入口，且入口与该空状态的原因对应。

### 推导三：加载态延迟出现

- **意图**：不制造视觉噪音。
- **推导**：300ms 内返回的请求若立即显示加载，会产生一闪而过的闪烁，比不显示更干扰。
- **结论**：超过 300ms 才显示加载指示。

### 推导四：长时间加载必须开口

- **意图**（回哪去）：用户需要知道还要等多久、能否离开。
- **推导**：10 秒以上的静默加载，用户无法判断是卡死还是进行中，只能刷新或强杀。
- **结论**：超过 10s 给出「仍在处理」提示；超过 30s 给出后台执行或放弃的选项。

### 推导五：报错三要素

- **意图**（核验 + 到哪去）：用户需要知道发生了什么、影响是什么、能做什么。
- **推导**：裸露错误码或英文堆栈，用户既无法理解也无法行动。
- **结论**：报错文案包含原因、影响、可执行动作。

### 推导六：成功反馈不阻断

- **意图**：成功是流程的结束，不是新流程的开始。
- **推导**：弹窗式成功提示要求用户再点一次关闭，为一件已完成的事增加一次多余操作。
- **结论**：优先用轻提示，自动消失。

## 3. 反证

| 拿掉 / 换掉什么 | 因果在哪一环断裂 |
|---|---|
| 空状态只写「暂无数据」 | 用户无法区分无数据 / 被筛选 / 无权限，只能猜测自己的处境 |
| 空状态无动作入口 | 页面成为死井，用户看到它却无事可做 |
| 移除加载反馈 | 用户无法确认系统是否收到请求，重复点击造成重复提交 |
| 10s 以上静默加载 | 用户无法判断卡死或进行中，只能刷新或强杀进程 |
| 报错只给错误码 | 用户既无法理解也无法行动，只能求助外部 |
| 报错不给恢复路径 | 用户卡死在错误页，必须自行寻找返回方式 |
| 成功用弹窗提示 | 为已完成的事增加一次关闭操作，打断用户节奏 |

## 4. 切片存档

| 状态 | 必备内容 | 生效条件 |
|---|---|---|
| 空（无数据） | 说明 + 创建入口 | 从未有过数据 |
| 空（筛选） | 说明 + 清除筛选 | 筛选后为空 |
| 空（无权限） | 说明 + 申请或返回 | 权限不足 |
| 加载 | 骨架屏或进度指示 | 超过 300ms |
| 加载（长） | 「仍在处理」+ 后台或放弃 | 超过 10s |
| 报错 | 原因 + 影响 + 重试 / 返回 | 恒定 |
| 成功 | 轻提示，2–4s 自动消失 | 恒定 |

| 项 | 值 | 生效条件 |
|---|---|---|
| 加载指示出现阈值 | 300ms | 恒定 |
| 长加载提示阈值 | 10s | 恒定 |
| 骨架屏形状 | 模拟真实内容布局 | 使用骨架屏时 |
| 可重试失败 | 必须提供重试按钮 | 恒定 |

> 以上是推导结论，不是法律。当意图判读改变时，需重新走第 2 段。
