# 弹窗 Modal

弹窗、抽屉、确认层。

## 1. 意图归属

**弹窗只在必须打断用户时才存在。** 它主要服务「核验」意图——用户在做出「做还是不做」的决定。

| 意图 | 弹窗承担的职责 |
|---|---|
| 核验 | 复述事实与后果，让用户在确权后决定 |
| 执行 | 承载流程中一个不可跳过的小决定 |

**判据：凡是能被内联解决的事，一律不用弹窗。** 弹窗会夺走用户的上下文，每一次弹出都在消耗用户的耐心预算。

## 2. 形态必然性

### 推导一：标题必须复述对象

- **意图**（从哪来）：用户必须确认这个弹窗针对的是哪一个对象、由哪个动作触发。
- **推导**：「提示」「确认」不携带任何对象信息，用户无法确认自己正在操作什么。
- **结论**：标题 = 动作 + 对象，如「删除项目 A」。

### 推导二：正文必须说明后果

- **意图**（核验）：确认的前提是知道代价。
- **推导**：不复述后果时，用户只能凭猜测决定，高代价操作的确认形同虚设。
- **结论**：正文说明影响范围与是否可逆。

### 推导三：主操作只有一个，且在最右

- **意图**：一次决定只对应一个前进方向。
- **推导**：两个实心按钮 → 决定点哪一个之前先停顿 → 打断的成本又被放大一次。
- **结论**：主操作唯一，位置最右；危险操作主按钮用危险色。

### 推导四：至少三种关闭途径

- **意图**（回哪去）：不同习惯的用户都需要一条退出路径。
- **推导**：只有关闭图标时，键盘用户与习惯「取消」的用户都被迫改变习惯；缺失 Esc 时，弹窗成为牢笼。
- **结论**：关闭图标 + 取消按钮 + Esc，三条并存。

### 推导五：提交失败不关闭弹窗

- **意图**（回哪去）：保住用户的现场。
- **推导**：失败即关闭时，弹窗内已填内容全部丢失，用户需从头再来。
- **结论**：失败保持弹窗打开并保留已填内容。

### 推导六：禁止嵌套

- **意图**（从哪来）：用户必须清楚自己在哪一层。
- **推导**：弹窗内再开弹窗时，用户关闭一层后不知道回到何处，层级感知失效。
- **结论**：嵌套上限 1 层。

## 3. 反证

| 拿掉 / 换掉什么 | 因果在哪一环断裂 |
|---|---|
| 标题写成「提示 / 确认」 | 用户不知操作对象，可能在错误对象上点下删除 |
| 正文不复述后果 | 确认形同虚设，用户凭猜测决定高代价操作 |
| 拿掉取消按钮 | 用户被迫执行一个正在犹豫的决策，只能强杀界面 |
| 只保留关闭图标 | 键盘用户与习惯取消的用户被迫改变习惯，退路单一 |
| 提交失败即关闭 | 已填内容全部丢失，用户需从头重填 |
| 允许嵌套弹窗 | 层级感知失效，关闭一层后不知回到何处 |
| 遮罩点击行为不统一 | 用户无法形成稳定预期，每次都要试探 |

## 4. 切片存档

| 项 | 值 | 生效条件 |
|---|---|---|
| 宽度 | 小 320–400 ／ 中 480–560 ／ 大 640px+ | 按内容量判定 |
| 内边距 | ≥ 24px | 恒定 |
| 标题格式 | 动作 + 对象 | 恒定 |
| 按钮区位置 | 底部右对齐，主操作最右 | 恒定 |
| 关闭途径数 | ≥ 3（关闭图标 / 取消 / Esc） | 非强制流程 |
| 嵌套层数上限 | 1 | 恒定 |
| 提交失败行为 | 保持打开 + 保留内容 | 存在表单时 |
| 遮罩行为 | 全局统一 | 恒定 |

> 以上是推导结论，不是法律。当意图判读改变时，需重新走第 2 段。
