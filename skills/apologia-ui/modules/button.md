# 按钮 Button

主次动作。

## 1. 意图归属

**按钮是「到哪去」的物理化身。** 它主要服务三类意图：

| 意图 | 按钮承担的职责 |
|---|---|
| 寻的 | 把命中的目标推进下一步 |
| 执行 | 推动流程前进 |
| 核验 | **降级为次要**——核验场景下高权重给信息，不给动作 |

**判据：一个视图只允许一个主按钮，因为一个视图只允许一个主意图。**

## 2. 形态必然性

### 推导一：文案必须是契约文本

- **意图**（到哪去）：用户点击前必须知道点击后发生什么。
- **推导**：「确定」「提交」不说明作用对象，用户无法预判后果，必须读完上下文才能判断。
- **结论**：文案为「动词 + 对象」，如「保存草稿」「删除这张卡片」。

### 推导二：主按钮唯一

- **意图**：主意图只有一个滑轨方向。
- **推导**：两个实心按钮并排 → 用户在每个按钮前停顿 → 决策成本翻倍。
- **结论**：一个视图一个主按钮（实心强调色），其余降级为次按钮（描边）或文字按钮。

### 推导三：主按钮落在滑轨末端

- **意图**（到哪去）：为宏观目标铺设阻力最小的滑轨。
- **推导**：主按钮位置与阅读流末端不一致时，用户需要回溯视线寻找它。
- **结论**：主按钮位于阅读流末端或右下，并与触控拇指热区重合。

### 推导四：危险操作必须拉开距离

- **意图**（常数二）：高代价 + 误触 → 用空间距离换取安全。
- **推导**：删除紧贴主按钮时，肌肉记忆导致误点。
- **结论**：危险按钮不与主按钮相邻；危险色 + 二次确认 + 复述对象。

### 推导五：加载态保持原宽度

- **意图**：不给用户制造新的不确定性。
- **推导**：点击后按钮尺寸跳动 → 布局位移 → 用户在等待中还要重新定位界面。
- **结论**：加载态锁死原尺寸，禁用重复点击。

### 推导六：形状由意图决定，不由组件库决定

| 意图 | 形状收敛 |
|---|---|
| 即时发起（呼叫、执行） | 圆形大触点——触碰即发生 |
| 进入下一层上下文（查看、前往） | 横向延伸的胶囊/长条——代表展开与深入 |
| 阅读确认（核验场景的标签） | 长条或卡片式容器——暗示阅读与确认事实 |

**同一个「拨号」功能，在即时呼叫意图下是圆形大触点，在核验意图下必须缩为次要弱化触点。形状不是风格选择，是意图推导的结论。**

## 3. 反证

| 拿掉 / 换掉什么 | 因果在哪一环断裂 |
|---|---|
| 去掉主次区分 | 用户在每个按钮前停顿，决策成本翻倍，滑轨方向不再唯一 |
| 文案换成「确定/提交」 | 用户不敢点，必须读完上下文才能判断后果 |
| 拿掉二次确认（不可逆动作） | 误触即造成不可逆损失，且用户当场无法察觉 |
| 危险按钮与主按钮相邻 | 肌肉记忆导致误点 |
| 点击后按钮尺寸跳动 | 布局位移，用户在等待中还需重新定位 |
| 禁用态静默灰掉 | 用户反复尝试一个不会响应的控件，且不知道为什么不响应 |
| 核验场景放大圆呼叫按钮 | 用户未确权即拨通，产生社交尴尬与流程错误 |

## 4. 切片存档

| 等级 | 形态 | 生效条件 |
|---|---|---|
| 主 | 实心强调色 | 每视图 1 个 |
| 次 | 描边 / 浅底 | 并列备选 |
| 文字 | 无边框 | 低频、辅助 |
| 危险 | 危险色 + 二次确认 | 失败代价高时 |

| 项 | 值 | 生效条件 |
|---|---|---|
| 主按钮高度 | 40–48px | 恒定 |
| 次按钮高度 | 32–40px | 恒定 |
| 触控目标最小值 | 44×44px | 触屏 |
| 同组按钮间距 | ≥ 8px | 恒定 |
| 主按钮位置 | 阅读流末端或右下 | 恒定 |
| 危险按钮位置 | 不与主按钮相邻 | 失败代价高时 |

> 以上是推导结论，不是法律。当意图判读改变时，需重新走第 2 段。
